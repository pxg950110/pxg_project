# 首页工作台设计 - 原型说明

## 一、原型概述

- **形态**：可运行的高保真页面原型（非静态图），复用门户真实技术栈（Vue 3 + Ant Design Vue 4 + 真实路由跳转），沿用 CRS 原型的仓库惯例。
- **位置**：`maidc-portal/src/views/prototype/workspace/`
  - `WorkspaceV2.vue` — 原型主组件
  - `mock.ts` — 按角色组分组的 mock 数据（结构对齐 PRD 7.1 的 v2 接口响应）
- **访问方式**：门户 dev 启动后访问 `http://localhost:3000/proto/workspace`（已注册于 `src/router/constantRoutes.ts`，命名 `ProtoWorkspaceV2`，不进菜单）。
- **生命周期**：仅供设计评审，正式实现后随目录整体删除（与 CRS 原型同规则）。

## 二、评审要点

1. **角色视角切换器**（页面顶部）：在 临床·医生 / 科研·PI / 数据·管理员 / 治理·审计员 四个视角间切换，演示"同一骨架、角色化内容"：
   - 指标卡：临床组是随访四卡（今日到期 3 / 已超期 2 / 我的患者 86 / 本周完成 9），数据组是 v1 的模型四卡（证明向后兼容），治理组是用户/审计/权限拒绝/告警。
   - 待办源：临床组含 4 条随访待办（含超期 1 天、超期 7 天升级两种形态），其他组只有审批/标注等通用待办。
   - 快捷入口：四组各不相同，治理组含 5 个入口验证"最多 8 个、两行网格"。
   - 队列动态卡：仅临床/科研组出现（通知卡下方）。
2. **快捷患者检索**（欢迎栏右侧）：输入任意内容回车 → 真实跳转 `/data/cdr/patients?keyword=xxx`（P1 落地时需患者列表支持 keyword 参数）。
3. **随访待办联动**：点击「开始随访」或随访行标题 → 跳转既有的 CRS 随访工作台原型 `/proto/crs/workbench`，可完整走"量表填写 + 治疗记录"执行流，验证工作台 → 执行的任务链路。
4. **超期升级提醒**：临床组"周玉兰 · 术后1月随访"超期 7 天，展示红色超期 tag + ⚠ tooltip（超期 > 7 天已升级通知负责医生），对齐 CRS 原型规则。
5. **交互演示**：通用待办「完成」、通知「已读/全部已读」、卡片点击跳转、刷新按钮均为可操作状态（操作本地 mock 副本，刷新角色即还原）。

## 三、v2 与 v1 的差异映射

| 区块 | v1（现状） | v2 原型 | 后端来源 |
|------|-----------|---------|----------|
| 欢迎区 | 仅问候+日期（userName 后端空串） | + 角色标签 + 机构科室 + 快捷患者检索 | welcome 补全；检索为前端直跳 |
| 指标卡 | 固定模型 4 卡（MetricsInfo 对象） | cards 数组通用渲染，按角色组 | `cards[]`（新增） |
| 待办 | personal_task，tab 全部/审批/标注/其他 | + 随访 tab、todoStats 头部统计、随访行专用渲染 | todos 扩展 + `todoStats`（新增） |
| 通知 | 5 条站内信 | 同 v1，类型增加 COHORT | notifications（微调） |
| （新增） | — | 专病队列动态卡（临床/科研） | `cohortDigest[]`（P1） |
| 快捷操作 | 硬编码 4 项 | 按角色组，前端 hasPermission 兜底 | quickActions（角色化） |

## 四、mock 数据 → 真实接口映射

| mock 字段 | 真实来源 |
|-----------|----------|
| `cards`（CLINICAL） | `cdr.c_followup_task` 今日/超期/本周完成计数；CDR 患者 DEPT 范围计数 |
| `cards`（DATA） | 沿用 `WorkspaceMetricsRepository`（v1） |
| `cards`（GOVERNANCE） | P1：audit/msg 服务 Feign 聚合（P0 降级复用 DATA 卡片） |
| `todos`（FOLLOWUP） | 新增 FollowupTodoProvider 直查 `c_followup_task` |
| `cohortDigest` | 队列同步/AI 建议/KB 发布事件最近 3 条 |
| `quickActions` | WorkspaceService 按角色组静态配置 + permission 字段 |
