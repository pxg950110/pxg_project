# 首页工作台设计 - 功能需求文档（PRD）

## 一、产品定位

MAIDC（Medical AI Data Center）门户的**登录后第一屏**：以"个人工作台"形态聚合该用户角色最关心的指标、待办、消息与功能入口，让每类用户 10 秒内看到"今天该做什么、从哪里开始"。

- 升级对象：现有 `/dashboard/workspace`（v1，2026-04-21 上线），v2 为**角色化内容升级**，不改导航结构、不改路由。
- 定位原则：**同一骨架，角色化内容**——不为每个角色单独做页面，而是聚合接口按角色组返回不同的卡片/待办/入口数据。

## 二、目标用户

平台全部 8 类角色（`docker/init-db/17-permission-system.sql`），按使用场景聚合为 4 个角色组（roleGroup）：

| 角色组 | 角色 | 核心场景 | 工作台关注点 |
|--------|------|----------|--------------|
| CLINICAL 临床组 | doctor 临床医生、nurse 护士 | 专病随访执行、患者诊疗参考 | 今日/超期随访、我的患者、知识库与检索入口 |
| RESEARCH 科研组 | researcher_pi 科研负责人、researcher 科研成员 | 队列构建、数据提取与研究 | 队列规模、导出审批、数据集、AI 入组建议 |
| DATA 数据组 | data_admin 数据管理员、ai_engineer AI 工程师 | 数据治理、模型全生命周期 | 模型/部署/推理指标、质控与 ETL 待处理项 |
| GOVERNANCE 治理组 | admin 系统管理员、auditor 审计员 | 平台治理与合规 | 用户、审计事件、权限拒绝、告警 |

多角色用户取"最宽角色组优先级 CLINICAL > RESEARCH > DATA > GOVERNANCE"中第一个命中的组（与权限系统 `widest()` 语义一致的可视化对齐）。

## 三、客户需求

1. **临床用户**（当前最大的痛点群体）："打开系统看到的是模型推理量，跟我没关系；我今天要随访谁、谁超期了，得自己点进随访页面找。" → 随访待办进第一屏。
2. **科研用户**："队列昨天同步进来多少人、我的导出申请卡在谁那里，希望能一眼看到。" → 队列动态与审批待办进第一屏。
3. **数据/治理用户**：延续 v1 的模型指标与审批待办，补充质控、审计、告警视角。
4. **全部用户**：常用功能入口按角色前置（v1 硬编码 4 个模型向入口）；医生高频的"找患者"动作提供全局快捷检索。
5. **平台侧**：权限系统上线后需要角色差异化的"可视化验收"，工作台是最直观的呈现位置。

## 四、功能需求

### FR1 角色化指标卡（P0）

- 聚合接口返回 `cards: MetricCard[]`（key/label/value/suffix/icon/route/tone），前端通用渲染，卡片可点击跳转对应业务页。
- 各角色组卡片定义：

| 角色组 | 卡片（label · 数据来源） |
|--------|--------------------------|
| CLINICAL | 今日随访到期（c_followup_task）· 已超期随访（c_followup_task）· 我的患者（CDR 患者，DEPT 范围）· 本周完成随访（c_followup_task） |
| RESEARCH | 在管队列（disease_cohort）· 队列患者总数（cohort_patient 汇总）· 待审批导出（审批待办）· 研究数据集（RDR dataset） |
| DATA | 模型总数 · 活跃部署 · 今日推理 · 待处理质控（沿用 v1 数据源 + 质控计数） |
| GOVERNANCE | 平台用户 · 今日审计事件 · 今日权限拒绝 · 活跃告警（P0 降级：复用 DATA 卡片；专属指标 P1 经 Feign 补齐） |

- tone 语义：primary 蓝色强调、danger 红色告警（超期/权限拒绝）、success 绿色（完成量）、warning 橙色（待处理）。

### FR2 待办中心升级（P0）

- 待办类型扩展：`FOLLOWUP`（新增）+ APPROVAL / LABELING / DATA_QUERY / OTHER（沿用）。
- 数据源合并：`maidc_task.personal_task`（存量）+ `cdr.c_followup_task`（新增 FollowupTodoProvider，同模块直查；按当前用户为负责护士/医生过滤，DEPT scope 生效）。
- 筛选 tab：全部 / 随访 / 审批 / 标注 / 其他（DATA_QUERY 归入其他），tab 上带数量 badge。
- 卡片头部统计：`今日到期 n`、`已超期 n`（超期>0 红色）。
- 随访待办行专用渲染：患者姓名 · 阶段、必评量表 tag（红）、到期日、超期天数（红）、超期>7 天显示升级提醒 icon（对齐 CRS 原型 `CrsWorkbench.vue` 规则）。
- 操作语义区分：随访待办**不在工作台直接完成**，提供"开始随访"按钮跳随访工作台执行（量表+治疗记录同事务提交）；通用待办保留 v1 的行内"完成"（`PUT /workspace/todos/{id}/complete`）。

### FR3 快捷入口角色化（P0）

- `quickActions` 由服务端按角色组下发；前端用 `hasPermission` 对 route 所属权限码二次兜底过滤。
- 各组默认入口（最多 8 个，两行网格）：

| 角色组 | 入口 |
|--------|------|
| CLINICAL | 患者检索 /data/cdr/patients · 临床检索 /data/cdr/search · 专病知识库 /data/cdr/disease-kb · 随访工作台（路由随 CRS 平移确定） |
| RESEARCH | 专病队列 /data/cdr/disease · 临床检索 · 知识库问答 · 研究项目 /data/rdr/projects · 数据集 /data/rdr/datasets |
| DATA | ETL 管道 /etl/pipelines · 数据源 /etl/datasources · 质量检测 /data/cdr/quality-results · 新建模型 /model/list · 新建评估 /model/evaluations |
| GOVERNANCE | 系统总览 /dashboard/overview · 操作审计 /audit/operations · 数据访问审计 /audit/data-access · 用户管理 /system/users · 告警中心 /alert/active |

### FR4 欢迎区补全（P0）

- 后端 `welcome` 返回真实 userName 与主角色名（v1 返回空串由前端兜底）；前端展示问候语（按时段）、日期、机构/科室、角色标签。

### FR5 快捷患者检索（P1）

- 欢迎栏右侧检索框：输入姓名/住院号回车 → `/data/cdr/patients?keyword=xxx`（患者列表需支持 query 参数透传）；命中唯一患者 ID 时直达 `/data/cdr/patient/:patientId`（患者 360）。
- 仅对具备 `cdr:read` 权限的角色组显示（CLINICAL/RESEARCH/DATA）。

### FR6 专病队列动态卡（P1）

- 通知卡下方新增可折叠卡（仅 CLINICAL/RESEARCH 组返回数据）：最近 3 条队列事件——同步完成（新增 n 人）、AI 入组建议待审（m 条）、知识库条目更新。
- 数据来源：队列同步 MQ 事件落库后的最近记录 + KB 发布事件。

### FR7 指标卡自定义（P2）

- 用户可在卡片编辑模式中显隐/排序本组卡片，偏好先存 localStorage（`maidc-workspace-cards`），量级上来后再评估 user_pref 表。
- 迷你趋势图：推理量/随访完成量 7 日 sparkline（echarts，portal 已有依赖）。

### FR8 布局偏好与公告（P3）

- 紧凑/舒适密度切换；全局公告条（管理员在消息中心发布，工作台置顶展示 N 天）。

### 优先级汇总

| 优先级 | 功能 | 交付判断 |
|--------|------|----------|
| P0 | FR1 角色化指标卡、FR2 待办中心接入随访、FR3 快捷入口角色化、FR4 欢迎区补全 | 随访前端平移前必须就绪 |
| P1 | FR5 快捷患者检索、FR6 队列动态卡 | 随访平移同版本 |
| P2 | FR7 卡片自定义 + 趋势图 | 用户反馈驱动 |
| P3 | FR8 布局偏好、公告条 | 远期 |

## 六、交互设计

1. **待办点击**：随访行点击/「开始随访」→ 随访工作台并定位该患者任务；通用待办点击 → 按 sourceType 跳审批/标注页（v1 行为）；「完成」仅对通用待办出现，二次确认后置灰→移除。
2. **超期升级提醒**：超期天数红色加粗；>7 天追加 ⚠ icon 与 tooltip「已升级通知负责医生」（对齐 CRS 原型）。
3. **通知**：未读左侧蓝色竖条；点击已读+跳转（routeMap 增加 COHORT → 队列详情）；「全部已读」沿用 `PUT /messages/read-all`。
4. **刷新**：手动刷新按钮（含待办/卡片/通知全量重取）；不做轮询与 WebSocket（沿用 v1 YAGNI 决策）。
5. **加载与降级**：聚合接口部分失败时，失败区块显示"数据加载失败 + 重试"，其余正常；随访源查询失败仅影响随访待办与相关卡片（显示"—"）。
6. **角色切换**（无切换功能）：内容完全由服务端按登录角色返回；多角色用户按角色组优先级取第一命中组。

### 7.2 后端实现要点

- `WorkspaceController` 需获得当前用户角色：**方案 A（推荐）** 网关认证过滤器透传 `X-User-Roles`（逗号分隔）；方案 B：WorkspaceService Feign 回查 auth `/users/{id}`。P0 采用 A。
- `WorkspaceService.getDashboard(userId, orgId, roles)`：按角色组路由 cards 构建；新增 FollowupTodoProvider（直查 `cdr.c_followup_task`：PENDING + due_date = today / < today，按负责护士或医生 = 当前用户）；quickActions 按角色组静态配置 + permission 字段。
- DEPT scope：随访待办、我的患者卡均须按 `DataScopeHelper` 过滤（doctor/nurse 为 DEPT，researcher 为 PROJECT 内可见患者）。

### 7.3 范围控制（本期不做）

- governance 组专属指标（审计事件/权限拒绝/告警计数）跨服务取数 → P1 Feign 补齐，P0 复用 DATA 卡片。
- 卡片自定义、sparkline、公告条 → P2/P3。
- 不新增微服务、不新增数据库表（`cdr.c_followup_task` 已存在）。

### 7.4 非功能

- 聚合接口 P95 < 800ms（随访直查 + 现有 Feign 并行化，可用 CompletableFuture）。
- 待办列表上限 20 条，通知 5 条（沿用 v1）。
- 权限：接口级 `workspace:read`；卡片/入口内容级由角色组 + permission 双重控制。
